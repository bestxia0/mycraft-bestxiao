# 多 Agent 并行协作规范（详解）

> 速查版在 `AGENTS.md` 第 3 节。本文是**执行细则**：怎么起会话、怎么隔离、怎么合并、出事怎么办。
> 谁都可以读；只有协调官（C0）能改 `program/BOARD.md`。

---

## 1. 一张图看懂

```text
        ┌──────────────┐
        │ C1 关卡策划   │  把「小朋友想玩什么」写成玩法设计（写进任务卡）
        └──────┬───────┘
               │ 设计段
        ┌──────▼───────┐        ┌──────────────────────────────┐
        │ C0 协调官     │───────▶│ program/BOARD.md（唯一事实源）│
        │ 拆卡 / 派卡   │        │ program/tasks/TC-*.md（任务卡）│
        └──┬────┬───┬───┘        └──────────────────────────────┘
           │    │   │
   ┌───────▼┐ ┌─▼──────┐ ┌▼─────────┐
   │C3 关卡  │ │C4 内容 │ │C2 引擎    │   并行干活（各在自己的分支 / worktree）
   │levels/  │ │content/│ │engine/    │
   └───┬────┘ └───┬────┘ └────┬─────┘
       │          │           │
       └──────────┴─────┬─────┘
                        │ 回执（RECEIPT）
                 ┌──────▼───────┐
                 │ C5 测试       │  跑脚本 → pass 才 done
                 └──────┬───────┘
                        │ 通过
                 ┌──────▼───────┐
                 │ C6 文档       │  README / AGENTS / CHANGELOG
                 └──────────────┘
```

**关键**：C0 在中间**只传卡不改码**；C5 在最后**只验不改码**。

## 2. 一张任务卡的一生

| 阶段 | 谁 | 动作 | 文件变化 |
| --- | --- | --- | --- |
| 1 拆卡 | C0 | 复制模板，写 TASK 段 | 新增 `program/tasks/TC-00NN-*.md`，`BOARD.md`「待认领」加一行 |
| 2 认领 | 执行者 | 填「角色」「状态: claimed」 | 卡里改状态；`BOARD.md` 挪到「进行中」由 C0 做 |
| 3 开工 | 执行者 | 状态: doing + 开始时间 | 只动自己名下的文件 |
| 4 自测 | 执行者 | 跑 `scripts/check.sh` 等，写 RECEIPT | 卡里写命令 + 输出 |
| 5 交活 | 执行者 | 状态: review | 通知 C0 / C5 |
| 6 验收 | C5 | 跑全套脚本，写 `program/qa/<卡号>.md` | 卡里写 QA 结论 |
| 7 归档 | C0 | 状态: done | `BOARD.md` 挪到「已完成」；C6 更新 CHANGELOG |

**卡住的卡**：写 BLOCK（卡在哪 / 等谁 / 已做部分）→ 状态 `blocked` → C0 挪到「三、阻塞」。

## 3. 四种消息的写法（照抄）

**TASK（协调官写）**
```text
要做什么：一句话说人话
验收标准：可测的清单（每条都要能被命令或截图证明）
允许改的文件：具体到路径
不许改的：具体到路径（要改先发 CHANGE）
依赖：卡号 / 无
```

**RECEIPT（执行者写）**
```text
改了哪些文件：
怎么验证的：命令 + 关键输出（别写「测过了」）
遗留问题：
```

**BLOCK（执行者写）**
```text
卡在哪：
等谁 / 等什么决定：
我先做了哪部分：
```

**CHANGE（任意角色 → C2/C4）**
```text
我需要什么新能力：
为什么要（哪个玩法卡住了）：
兼容要求（老关卡必须照常跑）：
影响面（哪些文件 / 文档要跟着改）：
```

## 4. 物理隔离：分支 / worktree 怎么用

**为什么**：两个 Agent 在同一个目录里同时写文件 = 互相覆盖。所以一人一分支。

```bash
cd /Users/xiao/workspace/mycraft-bestxiao

# C0 先保证主干是干净的
git status
git add -A && git commit -m "chore: 建卡 TC-0003"

# 每个执行者开一条分支（示例：关卡开发）
git switch -c feat/tc-0003-mole-garden
# …干活、提交…
git add -A && git commit -m "feat(level): 打地鼠庭院（TC-0003）"

# 回到主干合并（C0 做；热点文件尤其要串行）
git switch main
git merge --no-ff feat/tc-0003-mole-garden
```

**能并行的**（不同文件夹，天然不冲突）：
两个 C3 各做一关、两个 C4 各写一个题库分类、C2 改引擎 + C3 写关卡（只要 C3 不用新 API 之前先等 C2 合并）。

**必须串行的**（热点文件）：
`src/levels/index.js` 加行、`src/content/banks/index.js` 加行、`index.html` 加 `<script>`。
做法：各自先把卡做到「只差一行」，再由 C0 按顺序合并；**同一时间只让一个人碰它**。

**没有 git 也能干**：那就**严格按文件夹分工**，并且同一时间只让一个会话改热点文件。
（不过强烈建议用 git，出错能回退。）

## 5. 并发冲突了怎么办（典型场景）

| 场景 | 处理 |
| --- | --- |
| 两个 Agent 都改了 `src/levels/index.js` | C0 手动合并成两行；**下不为例**，以后先约 |
| C3 想给关卡加一个引擎没有的能力 | 写 CHANGE → C2 做完 → C3 再基于新 `main` 继续 |
| C4 改题库导致老存档 key 变了 | **禁止**。老 key 必须能用兼容函数读出来（见 D-005） |
| 两个人改了同一个关卡文件夹 | 这属于编队错误（一人一关），C0 指定一个人重做，另一个换卡 |
| 做完发现老关卡坏了 | `regress-all.sh` 会抓到它 → 卡回 `doing`，修完再验 |

## 6. 验收门（DoD）逐条对照

- [ ] 只改了自己名下的文件（`git diff --name-only` 看一眼就知道）
- [ ] `zsh scripts/check.sh` 全绿
- [ ] 相关专项脚本跑过（新关卡：进关 → 通关 → 结算 → 回广场；战斗：`test-arena.sh`）
- [ ] `zsh scripts/regress-all.sh` 四个老关卡全过
- [ ] 卡里贴了命令 + 关键输出（不是「应该没问题」）
- [ ] `program/CHANGELOG.md` 有这次版本条目；改结构时 `AGENTS.md` / `README.md` 同步

## 7. 常见问题（FAQ）

**Q：家长一个人，真的需要这么多角色吗？**
A：不需要全上。最少两个：一个做（C3/C4），一个验（C5）。
「验」这一步千万别省 —— 小朋友玩到一半卡住比没加关卡更糟。

**Q：一个会话能不能同时做两关？**
A：可以，但要在 `BOARD.md` 里同时占两张卡，而且**两关的文件夹不要是同一个**。
如果两关都要改 `src/levels/index.js`，就串行加行。

**Q：AI 说「我做完了」，我怎么知道可信？**
A：看 RECEIPT 有没有**命令 + 输出**。没有就走 C5（`zsh scripts/regress-all.sh` 一跑就知道）。

**Q：想临时试试新玩法，要不要开卡？**
A：小实验直接改 + 不提交；**但只要想留下来给小朋友玩，就必须开卡**（否则过两天就没人记得为什么这么写）。

**Q：`work/` 里的截图和日志要提交吗？**
A：不要（`.gitignore` 已经排除）。要长期保存的图放 `docs/preview/`。
