# 关卡设计规范

本文件定义**关卡设计卡**（Level Card）的字段、写法与命名规则。
设计卡是"小朋友的想象"和"游戏实现"之间唯一的一份契约。

---

## 1. 一张设计卡长什么样

复制下面模板新建关卡（或用 `scripts/new-level.sh` 自动生成）。
下面这张是**演示字段写法的例子**（借 2026-10-23 的一个「点子」当样板，这个点子还没做进游戏）；
**游戏里真实关卡的完整卡**见 `levels/L01-谜语森林.md`。

```markdown
# 示例卡 · 找风扇，装进小房子，通上电（点子，未实现）

- 状态：点子（未实现 —— 见 `levels/_ideas/`）
- 游戏内顺序：**没有**（还没做进游戏）

- 小朋友口中的第几关：第一关
- 游戏内顺序：1（待确认）
- 更新：2026-10-24

## 原话（E0）

> "进入传送门之后，第一关就是找风扇，把它装进旁边的一个小房子，然后再给它充上电。"
> "如果还是错的，就可以直接装了，但是不用充电器。"

## 场景

一间小房子 + 周围可以乱走的一片区域，角落里藏着开关。

## 道具

| 道具 | 作用 | 从哪来 |
|------|------|--------|
| 风扇 | 装到小房子上 | 场景里自己找 |
| 充电器 | 给风扇通电 | 场景里自己找 |
| 开关 | 接通电源 | 藏在别的角落 |

## 动作

1. 找到风扇
2. 把风扇装进旁边的小房子
3. 找到开关，给风扇通电

## 目标（怎么算过关）

风扇装好并且转起来，房间有风。

## 规则（硬约束）

- 开关在别的角落，要自己找；找错了就继续找，**不提示**。
- 允许替代路径：找不到充电器时，可以**不充电直接装**，也算完成。
- 没有失败惩罚，不会弹出"正确答案"。

## 机制映射（给实现用）

| 玩法 | 实现手段 | 触发 → 变化 → 反馈 |
|------|----------|--------------------|
| 风扇/充电器 | 可拾取道具（背包里有图标） | 走近 → 拾取 → 叮一声 + 进入背包 |
| 小房子 | 可进入的封闭空间 + 安装槽位 | 拿着风扇靠近槽位 → 安装 → 风扇出现在墙上 |
| 开关 | 场景中的可交互方块，位置分散 | 碰到 → 通电 → 风扇开始转 + 风声 |
| 过关 | 条件判定 | 风扇已安装 &&（已通电 \|\| 走替代路径）→ 显示下一关入口 |

## 待确认（E2）

- [ ] 过关判定是否必须"转起来"，还是"装上就算"？
- [ ] 替代路径要不要也显示"完成"动画？

## 试玩记录

| 日期 | 结果 | 卡在哪 | 小朋友原话 |
|------|------|--------|-----------|
| | | | |

## 变更日志

| 日期 | 改了什么 | 为什么 |
|------|----------|--------|
| 2026-10-24 | 建卡 | 按 2026-10-23 口述记录整理 |
```

## 2. 字段说明

| 字段 | 必填 | 写法要求 |
|------|------|----------|
| 状态 | 是 | 只能取：草稿 / 待确认 / 就绪 / 开发中 / 可玩 / 已验收 |
| 小朋友口中的第几关 | 是 | 原话是几就写几，哪怕跳号（如"第三关的第二关"） |
| 游戏内顺序 | 是 | 数字，待确认时标注（待确认） |
| 原话（E0） | 是 | 逐字引用，不改错别字、不加标点化的改写 |
| 场景 | 是 | 用小朋友能看懂的话描述 |
| 道具 | 是 | 表格：道具 / 作用 / 从哪来 |
| 动作 | 是 | 编号列出玩家要做的事，按顺序 |
| 目标 | 是 | 一句话说清"怎么算过关" |
| 规则 | 是 | 包含硬约束与替代路径；"允许绕路"必须显式写出 |
| 机制映射 | 是 | 表格：玩法 / 实现手段 / 触发→变化→反馈 |
| 待确认（E2） | 否 | 实现者的推测和提案，勾选式 |
| 试玩记录 | 是（可空表） | 每次试玩追加一行 |
| 变更日志 | 是 | 每次改动追加一行 |

## 3. 机制映射词典

小朋友说的词 → 通用实现手段。新增词条随时补。

**✅ 已经实现过的机制（新关卡先照抄这些，别重造）**

| 小朋友的说法 | 机制归类 | 实现手段 | 反馈 | 游戏里在哪 |
|--------------|----------|----------|------|------------|
| 猜谜语 / 问问题 | 谜题判定 | 弹题（三选一）→ 判定对错 → 记进存档不重复 | **答错只给提示、不揭露答案** | L01 谜语森林 |
| 找宝箱 / 找东西 | 拾取 / 探索 | 场景里散落可交互物（可选择不放指路箭头） | 音效 + 背包图标变化 | L02 宝箱山谷 |
| 先答对才能打开 | 门槛式交互 | 交互时先弹题，答对才生效 | 面板答对 → 开箱动画 | L02 |
| 把装备炼成更好的 | 合成 / 升级 | 配方表（N 件低阶 → 1 件高阶） | 锻造面板 + 传说特效 | L02 铁匠铺 |
| 认字 / 学东西 | 学习系统 | 知识卡 + 随堂小测 | 卡片变绿 + 金币 | L03 汉字教室 |
| 打人 / 打对手 | 实时战斗 | 挥武器 + 命中判定 + 击退 + 僵直 | 掉血 + 双方弹开 + 音效 | L04 圆形擂台 |
| 场地越缩越小 | 缩圈 | 定时缩小可行走半径 | 圈外掉落 = 出局 | L04 |
| 骑马 | 载具 | 按 F 上马 → 玩家挂到载具上，WASD 控载具 | 座位抬高 + 跑动音效 | L05 沙漠逃亡 |
| 时间到了就送回小镇 | 限时 + 强制传送 | 倒计时归零 → **不弹失败面板**，直接回广场 | 音效 + 一句话提示 + 自动传送 | L05 |
| 箭头只给大概方向 | 模糊指引 | 目标方向 + 正弦摆动（±18° 以内） | 箭头左右晃，但大方向对 | L05 |
| 传送门 | 关卡切换 | 触发器 → 加载关卡 | 光效 + 转场 | 广场 |

**💡 还没实现的点子（机制先记着，做的时候往上面加一行）**

| 小朋友的说法 | 机制归类 | 打算怎么做 | 反馈 |
|--------------|----------|------------|------|
| 找东西（风扇、充电器） | 拾取 / 探索 | 场景内可拾取道具，随机或固定位置 | 音效 + 背包图标变化 |
| 装进去（小房子） | 安装 / 放置 | 安装槽位（靠近 + 按键） | 道具出现在墙上，位置固定 |
| 充电 / 通电 | 资源 / 开关序列 | 需要先激活"开关"方块 | 电源接通动画 + 环境音 |
| 开关在别的角落 | 探索型谜题 | 分散布置，无提示无指路箭头 | 找到时轻微提示（光/声） |
| 把绿色踩成白色 | 地块状态翻转 | 踩踏触发 tile 状态机（绿 → 白） | 颜色即时变化 + 踩踏音 |
| 空调 | 与风扇同类安装物 | 复用安装机制，换模型/效果 | 温度/风效变化 |
| 小房子 | 可进入空间 | 封闭 box 结构 + 门/入口触发器 | 进入时视角与音效变化 |
| 直接装（不用充电器） | 替代路径 | 判定条件里加 OR 分支 | 同样显示完成，不提示"你少了什么" |

> 词典的使用方式：**先写玩法，再查词典**。查不到就往词典里加一行，别硬套已有机制。

## 4. 命名规则

- 文件：`levels/L<两位序号>-<短名>.md`，例：`levels/L01-谜语森林.md`
- **序号 = 游戏内顺序**（以 `src/levels/index.js` 的清单 / `order` 为准），两位数，`L00`…`L99`。
  `L00` 留给中央广场（大厅）。
- **小朋友口述里的编号不算卡号**：口述的「第一关 / 第三关的第二关 / 第五关」只写进
  `transcripts/` 和卡里的「小朋友口中的第几关」字段（常常和游戏里的编号对不上，这很正常）。
- 还没做进游戏的点子：放 `levels/_ideas/<日期>-<名字>.md`，**不占卡号**
  （落地成代码时才在 `levels/` 开正式卡）。
- 短名：4–8 字，能一眼认出这关干什么
- 谜题的答案文件：`levels/answers/L<序号>-答案.md`（序号同卡号），**关卡内不出现答案**

## 5. 一关只教一件新事的检查

开卡时对着问一遍，任何一条不满足就拆关卡或删机制：

1. 这关的新机制，能用一句话说完吗？
2. 玩家进关卡后，10 秒内能猜到要做什么吗？
3. 卡住时有 ≥ 1 条出路吗（含"算了直接装"这类绕过方案）？
4. 这关有没有复用其他关卡的核心机制（有就是"延续关"，需在卡里注明）？
5. 这关有没有违背硬约束（唯一解 / 预置答案 / 失败惩罚）？

## 6. 谜题关专项规则（所有谜题关都用，先例见 L01 谜语森林）

来自小朋友的硬约束：**"你不要给我设置答案""如果错了，你再给我看答案"**。

落地方式：

| 要求 | 做法 |
|------|------|
| 关卡内不出现答案 | 关卡脚本、字幕、提示语里都不含答案文本 |
| 答案可维护 | 答案写在 `levels/answers/<关卡>-答案.md`，标注"实现方可见、游戏内不可见" |
| 揭示时机 | 只在小朋友答错后由大人给出；游戏内不自动揭示 |
| 判断题 | 记录小朋友每次作答，用于后续调整难度 |
| 避免干扰 | 场景里不放"提示牌"式的答案线索，除非小朋友自己要求 |

## 7. 不做什么（负面清单）

- 不加指路箭头、不加任务清单式的"当前目标"浮层（除非小朋友要求）。
- 不加"闯关失败 / 重试"界面。
- 不把大人的设计习惯（教程、成就、排行榜）塞进关卡。
- 不为"玩法数量"硬凑关卡。
