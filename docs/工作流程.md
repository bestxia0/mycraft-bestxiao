# 工作流程：从小朋友的一句话，到一关能玩的游戏

适用范围：所有新增/修改关卡的场景。
一句话总览：**口述原文 → 转写归档 → 结构化拆解 → 关卡设计卡 → 机制映射 → 开发 → 小朋友试玩 → 回写归档 → 提交 + 打版本**。

---

## 0. 角色

| 角色 | 是谁 | 负责什么 | 不负责什么 |
|------|------|----------|-----------|
| **关卡设计师** | 小朋友 | 讲玩法、拍板好不好玩、试玩验收 | 不管技术实现 |
| **制作人 / 翻译** | 家长 | 录音、判定"这是不是一个关卡"、把口述整理成卡 | 不替小朋友改玩法 |
| **实现者** | AI + 引擎仓 | 机制映射、写代码、做出可试玩版本 | 不擅自改玩法、不预置谜题答案 |

硬规则：

- **小朋友的玩法是第一性的**。实现者觉得"这样不好玩"时，只能提建议，不能直接改。
- 小朋友说"你来帮我想一下吧"时，实现者要**主动出提案**（至少 2 个候选），而不是反过来问一堆问题。
- 谜题类关卡**不预置答案**，答案只在小朋友答错后才给出。

## 1. 证据分级

所有关卡内容都标来源等级，避免"AI 猜的东西"变成"小朋友的设定"：

| 等级 | 含义 | 写进哪里 | 写法 |
|------|------|----------|------|
| **E0** | 小朋友原话 | `transcripts/`、设计卡的原话引用 | 直接引用，不改字 |
| **E1** | 基于原话的整理 | 设计卡的场景/道具/动作/规则 | 标明 [整理] |
| **E2** | 实现者的推测或提议 | 设计卡的"待确认""提案" | 标明 [待确认] / [提案] |

> 规则：E2 内容**不得**在未获小朋友确认前升级为 E1，更不得写进 `transcripts/`。

## 2. 八步流程与门禁

每一步都有输入、产物、门禁。**门禁不过，不进下一步**。

### 步骤 1 · 采集（小朋友口述）

- 输入：小朋友自然的讲述（可能想到哪说到哪，编号跳来跳去）。
- 动作：录音（手机备忘录/语音输入均可），尽量不打断、不追问"应该怎样"。
- 产物：录音文件。
- 门禁：有可回放的录音或原始文本。**没有原始记录就没有关卡。**

### 步骤 2 · 转写归档

- 输入：录音。
- 动作：转写成文字，**逐字保留**，包括不通顺和重复的地方。
- 产物：`transcripts/<日期>-<主题>-口述.md`。
- 门禁：转写稿里能一眼找到每一关的原话。此文件**只增不改**。

参考命令（需本机装了 whisper.cpp 或 openai-whisper，二选一）：

```bash
# 方式 A：本地 whisper.cpp（离线）
whisper-cli -m ~/models/ggml-medium.bin -l zh -otxt ~/Movies/voice/口述.m4a

# 方式 B：openai-whisper（Python）
whisper ~/Movies/voice/口述.m4a --language Chinese --model medium --output_format txt
```

> 没装也不用卡住：直接用语音输入法听写成文字，手工贴进 `transcripts/`，一样满足门禁。

### 步骤 3 · 结构化拆解

- 输入：转写稿。
- 动作：把每段口述拆成五件事——**场景 / 道具 / 动作 / 目标 / 规则**。
- 产物：设计卡里的对应小节（可以直接用模板开卡）。
- 门禁：五件事都填得出来。填不出来的，回步骤 1 补问小朋友（一次只问一件事）。
- 特别注意：
  - 小朋友的关卡编号可能不连续（如"第一关 / 第三关的第二关 / 第三关的第四关 / 第四关 / 第五关"），**先记下来，不要自己重排**。
  - 口述里"如果错了就再找""实在不行可以不用充电器"这类话，是**规则**，不是废话。

### 步骤 4 · 关卡设计卡

- 输入：结构化拆解结果。
- 动作：用 `docs/关卡设计规范.md` 的模板开一张卡，落到 `levels/L<序号>-<短名>.md`。
- 产物：关卡设计卡（契约）。
- 门禁（三问全答得上）：
  1. 这关**只教**的一件新事是什么？
  2. 玩家怎么知道"过关了"？
  3. 卡住了怎么办（必须有出路，符合"无唯一解"）？

### 步骤 5 · 机制映射

- 输入：设计卡。
- 动作：把玩法名词翻译成实现手段（见 `docs/关卡设计规范.md` 的机制映射词典）。
  例：风扇 → 可拾取道具；小房子 → 可进入的封闭空间；充电 → 找到并激活开关方块；踩绿变白 → 踩踏触发地块状态翻转。
- 产物：设计卡里的"机制映射"小节。
- 门禁：每个机制都写清"触发条件 → 变化 → 反馈（看的听的）"。
  做不出来的机制，**回步骤 4 改设计**，不要在代码里偷偷简化。

### 步骤 6 · 开发（引擎仓）

- 输入：就绪的关卡设计卡。
- 动作：在引擎仓实现，每关一个可独立试玩的入口。
- 产物：可试玩版本 + 一个试玩入口（关卡切换/传送门）。
- 门禁：实现者自己先跑通一遍，确认无卡死（无法通关）路径。

### 步骤 7 · 小朋友试玩验收

- 输入：可试玩版本。
- 动作：**小朋友自己玩，大人在旁边看，不提示**。记录：卡在哪、笑了在哪、有没有自己发明新玩法。
- 产物：`levels/<关卡>.md` 底部"试玩记录"（日期 + 通过/未通过 + 卡住点 + 小朋友原话）。
- 门禁：满足其一即通过——
  - 小朋友能**独立通关**；或
  - 小朋友明确说"好玩"（哪怕卡住过）。
- 未通过：把卡住点写成新的规则/线索，回步骤 4 或 5，**不要加弹窗提示"正确答案是…"**。

### 步骤 8 · 回写归档

- 输入：试玩结果。
- 动作：更新设计卡状态、写变更日志、更新 `levels/README.md` 总表。
- 产物：状态推进到 `可玩` / `已验收`。
- 门禁：总表状态与设计卡状态一致（防止文档漂移）。

### 步骤 9 · 提交与版本标记（★每次测试通过都要做★）

- 输入：测试全绿的版本（`zsh scripts/check.sh` + 该关专项脚本 + `zsh scripts/regress-all.sh`）。
- 动作：**提交一次本地 git，并给这个版本打一个 tag**。
- 产物：一笔提交 + 一个版本号。
- 门禁：版本号**三处一致** —— `src/engine/namespace.js` 的 `Game.version`、
  `program/CHANGELOG.md` 的标题、git tag（`v<主>.<次>.<修>`）。

```bash
cd /Users/xiao/workspace/mycraft-bestxiao
zsh scripts/check.sh && zsh scripts/regress-all.sh   # 先全绿再提交
git add -A
git commit -m "feat(lv5): 第 5 关 · 沙漠逃亡"
git tag -a v2.4.0 -m "v2.4.0 · 第 5 关沙漠逃亡"
```

> 规则细节：**测试通过才提交**（没验证过不提交）；新关卡 = 次版本号 +1；
> **只提交本地，不要 push**（除非大人明确说要推上去）。
> 「哪一版是小朋友玩过的那版」靠 tag 认，所以 tag 一定要打。

## 3. 状态机

```
草稿 ──► 待确认 ──► 就绪 ──► 开发中 ──► 可玩 ──► 已验收
  ▲         │          │          │                    │
  └─────────┴──────────┴──────────┴────────────────────┘
        小朋友否掉了 / 发现设计不可行，就退回上一状态
```

| 状态 | 含义 | 谁推动 |
|------|------|--------|
| 草稿 | 只有口述碎片，还没成卡 | 制作人 |
| 待确认 | 卡写好了，等小朋友点头 | 小朋友 |
| 就绪 | 小朋友认可，可以开发 | 制作人 |
| 开发中 | 引擎仓在做 | 实现者 |
| 可玩 | 能试玩，等验收 | 实现者 |
| 已验收 | 小朋友玩通了/说好玩 | 小朋友 |

## 4. 常见分支怎么处理

| 情况 | 处理方式 |
|------|----------|
| 小朋友想不出来某关 | 实现者给 2 个提案，写进设计卡的"提案"，让小朋友挑 |
| 小朋友中途改主意 | 设计卡留变更日志（旧方案划掉不删），状态退回 `待确认` |
| 某个机制技术上做不出来 | 回步骤 4，用"能实现的等效玩法"替换，并说明差异 |
| 同一玩法重复出现 | 按理念 2（一关一机制）判重，第二关要换机制，或在卡里写明"延续关" |
| 口述里出现答案 | 挪到 `levels/answers/`，关卡内不允许出现答案文本 |
| 关卡顺序和小朋友说的不一致 | 以设计卡"游戏内顺序"为准，原话编号只做记录 |

## 5. 单关典型耗时（参考）

| 步骤 | 耗时 |
|------|------|
| 采集 + 转写 | 10 分钟 |
| 拆解 + 设计卡 | 20 分钟 |
| 机制映射 | 15 分钟 |
| 开发 | 半天 ~ 2 天（看机制） |
| 试玩验收 | 20 分钟 |

目标：**小朋友每讲一关，一周内能玩到**。
